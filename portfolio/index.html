Featured · Public repository

Jobscribe: a voice-to-invoice app, and the test suite behind it

TypeScript · React · React Native · Express · PostgreSQL · Vitest · Playwright · Jest

A tech records a job note on-site and the app turns it into a draft invoice. I built it full-stack (Express API, React dashboard, Expo mobile app, Prisma on PostgreSQL) and wrote the tests that protect the parts that handle money and customer data.

How it is tested

  • 115 API integration tests across 22 files, using Vitest and Supertest against a real PostgreSQL database instead of mocks. They cover auth, cross-tenant isolation, invoice send and void guards, Stripe webhook idempotency, subscription gating, SMS consent, the reminder scheduler and money math.
  • End-to-end: a Playwright test drives the real dashboard and backend on an isolated database: register a business, add a client, schedule a job, create an invoice and mark it paid.
  • Mobile: Jest and React Native Testing Library tests for the login flow every other screen depends on.
  • CI: three GitHub Actions workflows (backend, dashboard, mobile) run on pushes and pull requests that touch each app. The backend workflow starts a Postgres 16 service container.

How the app works

  • Audio is stored in S3, transcribed with OpenAI Whisper, then billing fields are extracted as JSON by the Claude API into a draft invoice.
  • Stripe Connect direct charges and webhooks send money to each business's own account. Twilio handles SMS and node-cron sends overdue-invoice reminders.

Playwright · TypeScript · GitHub Actions

Defect reports

JB-001

Dashboard never shows the revenue trend

  • Severity: Medium
  • Priority: P2
  • Dashboard
  • Open
Steps
  1. Log in as an owner who has paid invoices.
  2. Open the Dashboard.
Expected
The README lists revenue trends as part of reporting, and the API already returns monthly revenue. A revenue-by-month view is shown.
Actual
Only four totals, job type, busiest days and job status are shown. There is no monthly revenue view.
Evidence
backend/src/routes/reports.routes.ts builds and returns revenueByMonth. dashboard/src/pages/Dashboard.tsx never reads it. It appears only as a type in dashboard/src/api/client.ts.
JB-002

Times ignore the business timezone setting

  • Severity: Medium
  • Priority: P2
  • Scheduling, Job detail
  • Open
Steps
  1. In Settings, set the timezone to America/Chicago.
  2. Create a job for 3:00 PM Central.
  3. Open Scheduling and the job from a browser set to Pacific time.
Expected
The job shows 3:00 PM Central, or at least names the timezone it is in.
Actual
The time is converted to the viewer's browser timezone with no zone label, so the same job reads as 1:00 PM.
Evidence
Dates use new Date(...).toLocaleString() with no timezone argument (JobDetail.tsx:225, Jobs.tsx:187). The organization timezone is read only by the reminder scheduler and the Settings page. The same gap exists server-side: reports.routes.ts:28 groups revenue by the server's local month.
JB-003

Large money amounts have no thousands separators

  • Severity: Low
  • Priority: P3
  • Dashboard
  • Open
Steps
  1. Use a business with more than $1,000 collected.
  2. Open the Dashboard.
Expected
Revenue collected reads $4,820.50.
Actual
It reads $4820.50, which is harder to scan at larger amounts.
Evidence
Dashboard.tsx:36-37 formats with toFixed(2) instead of Intl.NumberFormat.
